# AGENTS.md — Guidelines for AI Agents

This file is for AI coding agents working in `llm-router/`. Read it before making any changes. **MUST FOLLOW WITHOUT EXCEPTION.**

## About the Project

`llm-router` is a zero-bloat, self-contained OpenAI-compatible LLM routing gateway.

- Single binary + embedded Svelte SPA + embedded bbolt DB.
- Runtime deps only `cobra` (CLI) + `bbolt` (storage).
- Routes `ModelId = provider/model` (e.g. `openai/gpt-4o`, `kiro/claude-haiku-4.5`, `agents/my-agent`) to a provider `Adapter` + `CredentialPool` (LRU, 4-tier priority, exponential backoff, auto-refresh).
- Supports virtual `agents/` provider for multi-model orchestration.
- External adapters via `adapters.conf` → `.workspace/` + generated `adapters.go` + `go.work` (`sdk.Register`, mandatory workspace).

## Structure & Architecture

```
cmd/root.go              — CLI entrypoint, flags --web/--api/--db
internal/server/         — HTTP server, mounts dashboard (8080) and /v1 API (8081)
internal/services/
  token/                 — router-token issue/validate (bearer for /v1)
  router/                — ModelId → Adapter + Credential, LRU + retry
  provider/              — Provider CRUD
  credential/            — credential pool, usage stats
  agent/                 — agents/* virtual provider
  modelinfo/             — model metadata cache (1h TTL)
  metrics/               — 1m buckets, 90d retention
  maintenance/           — refresh + cleanup
  tokencount/            — slop-tokenizer wrapper
internal/repository/     — bbolt buckets (meta, admin, tokens, providers, credentials, agents, sessions, metrics, model_info, auth, token_index)
internal/dashboard/      — admin REST API (providers, tokens, agents, metrics)
internal/api/v1/         — OpenAI-compatible POST /v1/chat/completions, GET /v1/models
internal/models/         — shared wire types
internal/config/         — Config struct
providers/agents/        — built-in agents adapter
web/                     — Svelte SPA, `src/lib/generated/` is generated
adapters.go              — generated blank imports, DO NOT EDIT (generated by prepare-workspace)
adapters.conf            — external adapter registry: `<module>` per line
.workspace/              — local adapter clones (mandatory, gitignored) + `go.work` — ЕДИНСТВЕННОЕ место для разработки адаптеров
Makefile                 — dev tasks (see below)
```

Keep changes shallow — do not dive into service internals unless the task requires it.

## Adapters — Where To Write New Adapters

* Все внешние адаптеры живут ТОЛЬКО в `.workspace/<adapter-name>/` (напр. `.workspace/llm-router-adapter-opencode-zen/`).
* Не создавать папки адаптеров в `providers/`, в корне или рядом с проектом — `providers/` только для встроенного `agents`.
* Новый адаптер — отдельный Go-модуль `github.com/TheSlopMachine/llm-router-adapter-<name>` с `sdk.Register` в `init()` (`sdk:adapter.go:136`), обязательные файлы: `go.mod`, `adapter.go`, `client.go`, `models.go`, `transform.go`, `errors.go`, `README.md`, `.gitignore`.
* Регистрация: добавить `<module>` в `adapters.conf:5` → `make prepare-workspace` генерирует `adapters.go:1` + `go.work:5` + `go work sync`.
* Проверка: `make go-check` / `make start` (через `ModelId:26` → `opencode-zen/model`).

## Makefile Usage

All dev tasks are via `Makefile` in this directory. Do not run raw `go`/`npm` commands directly.

| Target | What it does |
|---|---|
| `prepare-workspace` | `stop` → clone adapters from `adapters.conf` to `.workspace/` + generate `adapters.go` + `go.work` (`go work sync`) |
| `prepare-frontend` | `stop` → `npm install --no-audit --no-fund` + `npm run build` in `web/` |
| `prepare` | `prepare-frontend` + `prepare-workspace` |
| `start` | `mkdir -p` dev DB/log dirs → `go build -o <temp>/llm-router-dev(.exe) .` → `nohup <tmpbin> --web 8080 --api 8081 --db ~/.local/llm-router/llm-router-dev.db > <temp>/llm-router-dev.log 2>&1 &` → pid in `<temp>/llm-router-dev.pid`. Prints `Dashboard: http://localhost:8080` + `API: http://localhost:8081/v1` |
| `stop` | `kill` pid from `<temp>/llm-router-dev.pid` (graceful → `kill -9`/`taskkill`/`powershell` fallback), `rm pid` |
| `restart` | `stop` + `start` |
| `status` | `running as PID X / not running` + `Log: <temp>/llm-router-dev.log` |
| `browser` | `open`/`xdg-open`/`powershell Start-Process http://localhost:8080` |
| `clean` | `stop` + `git clean -fdx` |
| `publish` | `prepare-frontend` + `prepare-workspace` + `GOOS/GOARCH` builds for `$(PUBLISH_PLATFORMS)` → `build/release/<os>_<arch>/` + `checksums.txt` |
| `go-check` | `go vet ./...` |
| `go-test` | `go test ./...` |
| `help` | usage |

Examples:
```bash
make start
make restart
make publish PUBLISH_PLATFORMS="linux/amd64 darwin/arm64"
make status
make prepare-frontend
```

Dev DB: `~/.local/llm-router/llm-router-dev.db` (auto-created). Temp files: `$(TEMP)/llm-router-dev.pid/.log/.exe` on Windows, `/tmp/...` on Unix.

## Verification After `make start`

`make start` (`Makefile:173`) builds to `TMP_BIN` and prints:

```
[>] Building dev binary to .../llm-router-dev.exe...
[>] Starting llm-router --web 8080 --api 8081 --db .../.local/llm-router/llm-router-dev.db --testing-key .../.local/llm-router/llm-router-dev.key (pid .../llm-router-dev.pid, log file:///.../llm-router-dev.log)...
[OK] Started PID <pid>
Dashboard: http://localhost:8080
API: http://localhost:8081/v1
API Key: <hex>   # == content of DEV_KEY file
```

Use that `API Key` as `Authorization: Bearer <key>` for `/v1` on `8081` (`internal/api/v1`). Key also stored in `DEV_KEY` file (`~/.local/llm-router/llm-router-dev.key` on Windows `C:/Users/<user>/.local/llm-router/llm-router-dev.key`).

Checks (after `make start` succeeds, `make status` shows running):

```bash
# models
curl -H "Authorization: Bearer $key" http://localhost:8081/v1/models
# chat completion — ModelId = provider/model (e.g. opencode-zen/gpt-5)
curl -H "Authorization: Bearer $key" -H "Content-Type: application/json" \
  -d '{"model":"opencode-zen/test","messages":[{"role":"user","content":"ping"}]}' \
  http://localhost:8081/v1/chat/completions
```

Windows PowerShell (`Invoke-WebRequest`):

```powershell
$key = (Get-Content $env:USERPROFILE/.local/llm-router/llm-router-dev.key).Trim()
Invoke-WebRequest -Uri http://localhost:8081/v1/models -Headers @{Authorization="Bearer $key"}
Invoke-WebRequest -Uri http://localhost:8081/v1/chat/completions -Method POST -Headers @{Authorization="Bearer $key"; "Content-Type"="application/json"} -Body '{"model":"opencode-zen/test","messages":[{"role":"user","content":"ping"}]}'
```

Logs: `LOG_FILE` (`.../llm-router-dev.log`, shown as `file:///...`), status via `make status` / `make stop`. Never use `curl` without the printed `API Key` — requests will be `401`.

## What is FORBIDDEN

1. **DO NOT LITTER WITH TEMPORARY FILES WITHIN THE PROJECT**
   All temporary files, logs, pids, dev binaries must go to `temp` (`$(TEMP)/` or `/tmp`) or `~/.local/llm-router/`. Never create `*.log`, `*.pid`, `*.tmp`, `llm-router.exe` in the project directory. Use the Makefile's `TMP_BIN/PID_FILE/LOG_FILE`.

2. **DO NOT RUN Start-Process, go run or go build -o ./llm-router.exe. Use "make start" instead. ABSOLUTE BAN ON DIRECT go run.**
   The ONLY supported way to run/build the dev server is `make start` (or `make restart`). It handles `DEV_DB` creation, `go build -o <temp>`, daemonization, pid/log, and port flags `--web/--api/--db/--testing-key`. Direct `go run .`, `go run -tags ... .`, `go build -o ./llm-router.exe`, or `Start-Process`/`powershell go run` bypass the pid/log contract and break `stop`/`status`/`restart` and `DEV_KEY` handling.
   FORBIDDEN in all forms: `go run .`, `go run ./...`, `go build -o .\llm-router.exe`, `Start-Process go`, `& go run`, `python -c "subprocess.Popen(['go','run',...])"`, or any wrapper that invokes `go run`/`go build` directly.
   ALWAYS use `make start` / `make stop` / `make restart` / `make status`. If a verification is impossible via `make start/stop/status` (custom ports, testing-key path, isolated DB, etc.), **STOP and ASK the user** — do not improvise a direct `go run` invocation.

3. **DO NOT RUN MUTABLE GIT OPERATIONS**
   Never run `git commit`, `git push`, `git reset`, `git checkout -f`, `git clean` directly. Use `make clean` (which does `stop` + `git clean -fdx`). Do not amend, force-push, or modify `adapters.conf` without going through `prepare-workspace`. Only commit when explicitly requested. Do not touch version control otherwise — no staging, no commits.

4. **DO NOT DELETE DATABASE FROM ~/.local/llm-router/**
   Never remove `~/.local/llm-router/llm-router-dev.db` (or `C:/Users/.../.local/...` on Windows). It holds dev credentials/tokens. Use `make start` which auto-creates the directory; do not `rm` the DB.

5. **DO NOT RUN RAW COMMANDS DIRECTLY WHEN THEY HAVE ALTERNATIVES (IN MAKE ACTIONS)**
   Never run raw `go vet`, `go test`, `npm install`, `npm run build`, `git clean` directly when a Makefile target exists (`go-check`, `go-test`, `prepare-workspace`, `prepare-frontend`, `clean`, etc.). Always use `make <target>` — it handles `stop`, env, and flags correctly. This is a strict rule.

6. **ABSOLUTE BAN ON go run — ASK BEFORE IMPROVISING**
   If you need a custom DB path, custom port, custom `--testing-key` file, or any isolated run for tests/verification, do NOT construct a `go run` command yourself. The `Makefile` `start` already covers `DEV_DB`/`DEV_KEY`/`TMP_BIN`/`PID_FILE`/`LOG_FILE`. If your scenario is not covered by `make start/stop/restart/status` with environment variables (`DEV_DB=... DEV_KEY=... make start`), **STOP and ASK the user** for permission/instructions instead of bypassing the Makefile.
