# AGENTS.md — Guidelines for AI Agents

This file is for AI coding agents working in `llm-router/`. Read it before making any changes. **MUST FOLLOW WITHOUT EXCEPTION.**

## About the Project

`llm-router` is a zero-bloat, self-contained OpenAI-compatible LLM routing gateway.

- Single binary + embedded Svelte SPA + embedded bbolt DB.
- Runtime deps only `cobra` (CLI) + `bbolt` (storage).
- Routes `ModelId = provider/model` (e.g. `openai/gpt-4o`, `kiro/claude-haiku-4.5`, `agents/my-agent`) to a provider `Adapter` + `CredentialPool` (LRU, 4-tier priority, exponential backoff, auto-refresh).
- Supports virtual `agents/` provider for multi-model orchestration.
- External adapters via `adapters.conf` → generated `plugins/plugins.go` (`sdk.Register`).

## Structure & Architecture

```
cmd/root.go              — CLI entrypoint, flags --web/--api/--db
internal/server/         — HTTP server, mounts dashboard (8080) and /v1 API (8081)
internal/services/
  token/                 — router-token issue/validate (bearer for /v1)
  router/                — ModelId → Adapter + Credential, LRU + retry
  provider/              — Provider CRUD
  credential/            — credential pool, usage stats
  agent/                 — agents/* virtual provider
  modelinfo/             — model metadata cache (1h TTL)
  metrics/               — 1m buckets, 90d retention
  maintenance/           — refresh + cleanup
  tokencount/            — slop-tokenizer wrapper
internal/repository/     — bbolt buckets (meta, admin, tokens, providers, credentials, agents, sessions, metrics, model_info, auth, token_index)
internal/dashboard/      — admin REST API (providers, tokens, agents, metrics)
internal/api/v1/         — OpenAI-compatible POST /v1/chat/completions, GET /v1/models
internal/models/         — shared wire types
internal/config/         — Config struct
providers/agents/        — built-in agents adapter
web/                     — Svelte SPA, `src/lib/generated/` is generated
plugins/                 — generated blank imports, DO NOT EDIT (generated by prepare-plugins)
adapters.conf            — external adapter registry: `<module> <40-char-commit>`
Makefile                 — dev tasks (see below)
```

Keep changes shallow — do not dive into service internals unless the task requires it.

## Makefile Usage

All dev tasks are via `Makefile` in this directory. Do not run raw `go`/`npm` commands directly.

| Target | What it does |
|---|---|
| `prepare-plugins` | `stop` → generate `plugins/plugins.go` from `adapters.conf` (`GOPROXY=direct go get <mod>@<hash>` + `go mod tidy`) |
| `prepare-frontend` | `stop` → `npm install --no-audit --no-fund` + `npm run build` in `web/` |
| `prepare` | `prepare-frontend` + `prepare-plugins` |
| `start` | `mkdir -p` dev DB/log dirs → `go build -o <temp>/llm-router-dev(.exe) .` → `nohup <tmpbin> --web 8080 --api 8081 --db ~/.local/llm-router/llm-router-dev.db > <temp>/llm-router-dev.log 2>&1 &` → pid in `<temp>/llm-router-dev.pid`. Prints `Dashboard: http://localhost:8080` + `API: http://localhost:8081/v1` |
| `stop` | `kill` pid from `<temp>/llm-router-dev.pid` (graceful → `kill -9`/`taskkill`/`powershell` fallback), `rm pid` |
| `restart` | `stop` + `start` |
| `status` | `running as PID X / not running` + `Log: <temp>/llm-router-dev.log` |
| `browser` | `open`/`xdg-open`/`powershell Start-Process http://localhost:8080` |
| `clean` | `stop` + `git clean -fdx` |
| `publish` | `prepare-frontend` + `prepare-plugins` + `GOOS/GOARCH` builds for `$(PUBLISH_PLATFORMS)` → `build/release/<os>_<arch>/` + `checksums.txt` |
| `go-check` | `go vet ./...` |
| `go-test` | `go test ./...` |
| `help` | usage |

Examples:
```bash
make start
make restart
make publish PUBLISH_PLATFORMS="linux/amd64 darwin/arm64"
make status
make prepare-frontend
```

Dev DB: `~/.local/llm-router/llm-router-dev.db` (auto-created). Temp files: `$(TEMP)/llm-router-dev.pid/.log/.exe` on Windows, `/tmp/...` on Unix.

## What is FORBIDDEN

1. **DO NOT LITTER WITH TEMPORARY FILES WITHIN THE PROJECT**
   All temporary files, logs, pids, dev binaries must go to `temp` (`$(TEMP)/` or `/tmp`) or `~/.local/llm-router/`. Never create `*.log`, `*.pid`, `*.tmp`, `llm-router.exe` in the project directory. Use the Makefile's `TMP_BIN/PID_FILE/LOG_FILE`.

2. **DO NOT RUN Start-Process, go run or go build -o ./llm-router.exe. Use "make start" instead.**
   The only supported way to run the dev server is `make start` (or `make restart`). It handles `DEV_DB` creation, `go build -o <temp>`, daemonization, pid/log, and port flags `--web/--api`. Direct `go run .`, `go build -o ./llm-router.exe`, or `Start-Process` bypass the pid/log contract and break `stop`/`status`/`restart`.

3. **DO NOT RUN MUTABLE GIT OPERATIONS**
   Never run `git commit`, `git push`, `git reset`, `git checkout -f`, `git clean` directly. Use `make clean` (which does `stop` + `git clean -fdx`). Do not amend, force-push, or modify `adapters.conf` without going through `prepare-plugins`. Only commit when explicitly requested. Do not touch version control otherwise — no staging, no commits.

4. **DO NOT DELETE DATABASE FROM ~/.local/llm-router/**
   Never remove `~/.local/llm-router/llm-router-dev.db` (or `C:/Users/.../.local/...` on Windows). It holds dev credentials/tokens. Use `make start` which auto-creates the directory; do not `rm` the DB.

5. **DO NOT RUN RAW COMMANDS DIRECTLY WHEN THEY HAVE ALTERNATIVES (IN MAKE ACTIONS)**
   Never run raw `go vet`, `go test`, `npm install`, `npm run build`, `go get`, `git clean` directly when a Makefile target exists (`go-check`, `go-test`, `prepare-plugins`, `prepare-frontend`, `clean`, etc.). Always use `make <target>` — it handles `stop`, env, and flags correctly. This is a strict rule.
